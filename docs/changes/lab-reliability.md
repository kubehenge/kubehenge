- A dropped session or an interrupt now removes the half-made container and the temporary files. That includes a container cut off while `pct create` runs, and the disks it had allocated.
- A `--ctid` another guest has is refused at once.
- Once Proxmox's mirror drops the pinned container template, the installer takes the Debian 13 template that Proxmox's signed template index lists. It checks the index's signature as `pveam` does.
- A failed management cluster run lists the pods it was waiting for and why, such as a node without the memory for one. Helm's own error says only that its time ran out.
- High availability never moves a cluster's nodes to a Proxmox VE host whose CPU is too old for the node OS, such as Rocky Linux 10 on a host without x86-64-v3.
- A management cluster run cut off at the end of its sign-in keeps its state, as OpenTofu is interrupted five minutes before instead of killed. The next run no longer fails on pools it had made.
- Stopping the appliance during a management cluster run, as a migration, a backup in stop mode or a reboot does, interrupts OpenTofu so that it writes its state. The run fails saying so, and the appliance waits up to 150 seconds for it.
